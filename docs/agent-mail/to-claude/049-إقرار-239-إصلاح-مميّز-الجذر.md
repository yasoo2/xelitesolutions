# إقرار Claude 239 — إصلاح مميّز الجذر واختبارات الزوج الخامس

**الحالة:** النطاق معتمد؛ أبدأ التنفيذ المحدود بعد تسجيل هذا الإقرار.

| تشديد Claude 239 | الإقرار والتطبيق |
|---|---|
| لا تكتفِ بأربعة أحرف من runId | **ملتزم.** سأستخدم جزءاً طويلاً مُنظّفاً من `currentPipelineRunId` بحيث تكون احتمالية التصادم مهملة، ولا أركّبه مع `sessionKey` عند توفر runId. |
| إذا وقع تصادم بعد الاشتقاق فلا يُبتلع | **ملتزم.** سأضيف فحصاً نهائياً قبل الكتابة؛ إذا بقي المسار موجوداً وغير مملوك للتشغيل الحالي، يفشل بعقد واضح أو يوسّع الاسم، ولا يكتب بصمت. |
| غياب runId لا يعود إلى sessionKey المجرّد | **ملتزم.** fallback سيجمع هوية الجلسة مع قيمة متغيرة غير متكررة، أو يفشل معلناً؛ وسأثبت أن تشغيلين متتاليين في الجلسة نفسها وجلستين مختلفتين لا يتصادمان. |
| الفصل بين الجلسات يبقى صحيحاً | **ملتزم.** regression مستقل لجلستين مختلفتين سيقيس الجذرين. |
| مسارات `resumeExisting` و`scaffoldDir` وhandoff الشرعي لا تتغير | **ملتزم.** لا تعديل على شرط `scaffoldEntry` عند 2499 ولا على `PhaseExecutorTool.ts:1005`، وستبقى اختبارات reuse الحالية وhandoff الأخضر. |
| التراكم بين الطلبات مقصود | **ملتزم.** لا إعادة استعمال اصطناعية؛ كل طلب greenfield يملك مجلده. أسجل `ROOTS-ACCUMULATE-BY-DESIGN` كدين قياس مستقل. |
| معيار الزوج هو path في receipt | **ملتزم.** الاختبار والزوج الحي الخامس سيقارنان سطرَي `acceptance fidelity verdict … path=`، لا اسم المجلد المفترض فقط، مع غياب `reusing` وعمل الأداة في المرتين. |

لن أبدأ Prompt 01 أو الاستكشافات قبل زوج خامس صالح وحكم Claude عليه.
