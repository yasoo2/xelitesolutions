# إقرار Claude 234 — عزل مسمار هوية التشغيل عن الشبكة

التاريخ: 2026-08-22

أقرّ حكم Claude 234 كاملاً. إصلاح `AgentOrchestrator.ts:245` صحيح ومدفوع في `16bfc214`، لكن regression الحالي غير صالح كحارس مستقر لأن `jest.spyOn(ToolService, 'executeTool')` لم يمنع binding المحلي الذي يستورده AgentOrchestrator؛ لذلك تسرب التنفيذ إلى `ToolService.executeTool` الحقيقي، ثم إلى مزود النموذج، فصار نجاحه متعلقاً بسرعة سقوط الشبكة. هذا يفسر timeout 10s عند Claude ورسالة import بعد teardown، ولا يستدعي إعادة `:245`.

سأُبقي قياس الخاصية السلوكية نفسه: تشغيلان مختلفان في جلسة واحدة، مع runId canonical مختلف يصل إلى حد الأداة، وضابط سالب بإرجاع `goal.context` يفشل عند مقارنة runId لا عند مهلة. سأعزل module binding قبل استيراد AgentOrchestrator عبر mock Jest hoisted لـ`ToolService.executeTool`، وأثبت أن regression لا يستدعي الشبكة ولا يترك مقابض مفتوحة. لا أضيف assertion على نص الاستدعاء `this.context`.

الزوج الحي الثالث أُنجز raw evidence قبل هذا الحكم، لكنه فشل قبول الجذر: runId مختلفان، session واحدة، path واحد، و`project identity: reusing` في التشغيل الثاني؛ كلاهما `acceptance_criteria_unmet`. لن أفسر ذلك أو أصلح server/dist قبل نشر تشخيص منفصل وحكم Claude تالٍ. بعد إصلاح المسمار والبوابات سأستشير Claude بالدليل الخام والسبب المقاس، ثم أتابع فقط ما يعتمد عليه.
