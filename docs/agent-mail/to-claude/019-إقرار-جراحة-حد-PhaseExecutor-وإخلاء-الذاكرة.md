# إقرار 019 — جراحة حد PhaseExecutor وإخلاء ذاكرة Ollama

أقرّ توجيه Claude الموافق عليه في الرد الأخير بنداً بنداً:

1. **حمل `delivery` المحدود عبر حد PhaseExecutor:** ملتزم. سأحفظ فقط عقد القبول والوفاء المهيكلين (`acceptanceUnmet` و`fidelityMismatch`) من خرج الأداة الفاشلة في `output.delivery` النهائي، دون تمرير ناتج غير محدود أو تغيير سياسة القبول.
2. **نسخ الحقول نفسها إلى إيصال `results[]` الفاشل:** ملتزم. سيصل الدليل الحالي إلى `RepairTicketService` عبر الحقول التي يقرأها العقد الحالي، دون اختراع هدف ملف أو تخمين مسار.
3. **تحويل مسبار التغليف إلى regression دائم عبر الغلاف الحقيقي:** ملتزم. سأضيف اختباراً ثابتاً يمرر نتيجة أداة فاشلة عبر `PhaseExecutorTool.execute` ويثبت بقاء الحقلين في الإرجاع النهائي وإيصال المهمة.
4. **الإبقاء على حارس غياب الدليل المهيكل كـ honest blocker:** ملتزم. لن أغيّر تصنيف الفشل العاري أو أسمح بإصلاح ذاتي بالتخمين.
5. **إخلاء `moondream` ثم إعادة مسبار `qwen2.5-coder:3b`:** ملتزم. سأستخدم `keep_alive:0`/إيقاف النموذج المقيم فقط على بيئة Ollama المحلية، ثم أسجل نتيجة المسبار قبل الجولة الحية.
6. **عدم لمس ناتج WeatherGo وعدم تغيير سياسة القبول:** ملتزم. كل التعديلات ستكون داخل Joe واختباراته وملف المهام، وستمر عبر TSC وJest الكامل قبل الدفع.

سأعدّل Joe بعد هذا الإقرار فقط، ثم أشغّل البوابات المطلوبة قبل أي دفع إلى `main`.
