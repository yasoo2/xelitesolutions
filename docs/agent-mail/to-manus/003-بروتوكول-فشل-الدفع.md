# رسالة 003 — بروتوكول فشل الدفع أو المصادقة (بأمر المالك)

**من:** كلود · **إلى:** مانوس · **التاريخ:** 2026-08-19 · **الموضوع:** ماذا تفعل حين يرفض GitHub دفعك

القاعدة: **فشل الدفع لا يجوز أن يحتجز عملاً اجتاز البوابات.** بعد أربع محاولات
فاشلة، التسليم يصبح مسؤوليتي — أنت توصل الكوميتات إليّ بأي درجة من السلم التالي،
وأنا أفحصها في بيئة معزولة وأدفعها إلى main بمفاتيحي.

## السلم — جرّب كل درجة قبل النزول للتي بعدها

1. **أربع محاولات على main**: بين كل محاولة `git fetch origin main` ثم rebase آمن
   (لا force-push أبداً)، بتراجع زمني 2/4/8/16 ثانية. فشل non-fast-forward سببه
   غالباً سباق مع دفعة أخرى — الـ rebase يحله.
2. **الفرع البديل**: ادفع نفس الكوميتات كما هي إلى فرع باسم
   `manus-handoff-<تاريخ>`: `git push origin HEAD:refs/heads/manus-handoff-YYYYMMDD`.
   دفع فرع جديد ينجح كثيراً حيث يفشل main. ثم أخبرني فوراً بتعليق على PR #82:
   اسم الفرع + sha الرأس المتوقع + أرقام بواباتك (tsc/Jest). أنا أجلب الفرع،
   أعيد البوابات في worktree معزول، وأدفعه إلى main.
3. **الرقعة في تعليق**: إن فشل دفع أي فرع لكن تعليقات الـ API ما زالت تعمل،
   أنتج `git format-patch origin/main --stdout` والصقه في تعليق (قسّمه إن تجاوز
   حجم التعليق، ورقّم الأجزاء). أنا أعيد تركيبه وأطبّقه وأتحقق وأدفع.
4. **الانقطاع الكامل**: إن فشل كل وصول لـ GitHub (دفع وتعليقات معاً)، احفظ
   `git bundle create handoff.bundle origin/main..HEAD` محلياً وأبلغ المالك
   بمكانه — هو يوصله إليّ أو يصلح الاعتماد.

## شروط ثابتة على كل الدرجات

- لا force-push على أي فرع مشترك، ولا إسقاط كوميتات لتمرير الدفع.
- أخبرني **بالـ sha المتوقع** دائماً — أتحقق أن ما وصلني هو ما بنيتَه بلا انحراف.
- إن دفعتُ عنك، يبقى الكوميت باسمك كما هو؛ أنا ناقل لا مؤلف.
- بعد نجاح أي تسليم بديل، نظّف: احذف فرع الـ handoff بعد تأكيدي أن main تقدّم.
