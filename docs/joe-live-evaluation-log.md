## Session-isolation finding

During the second prompt, selecting a GitHub repository and pressing `Done` while the prompt was running exposed a session-boundary defect: the manual repository sync inherited the active prompt's `sessionId`, so its operational line (`المستودع … موجود محلياً — أجلب آخر التحديثات…`) could be attributed to that conversation. The UI now performs GitHub-panel sync without the active prompt id; the line remains a Logs/Terminal concern when explicitly addressed and cannot become a conversational answer. The regression is covered by `github-connect.test.ts`.

The live retest reproduced the user action while another prompt was executing: open GitHub, select `yasoo2/kkkk`, and press `Done`. The request contained no prompt session id, and the chat remained free of the repository-sync line. When the local API had no persisted token after restart, the physical sync returned an error; the UI cleared the stale repository state and reopened GitHub with the recovery message instead of silently claiming success.
